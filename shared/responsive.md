# Responsive-бриф: адаптация kit-страниц под мобильные экраны

> Дополнение к `shared/brand.md`. Применяется поверх уже готовых страниц
> `kits/<slug>/index.html` — **это правка существующего файла, не
> переписывание с нуля**. Десктопный вид (≥960px) должен остаться визуально
> идентичным тому, что есть сейчас — меняем только поведение на узких экранах.

## 1. Брейкпоинты

- **Desktop** — `≥960px`: текущий вид без изменений (сайдбар зафиксирован
  слева и всегда виден, 4 KPI-карточки в ряд, шапка как есть).
- **Tablet/Mobile** — `<960px`: сайдбар становится off-canvas (см. п.3),
  KPI — 2 колонки.
- **Small mobile** — `<560px`: KPI — 1 колонка, тулбар фильтров — вертикальный
  стек на всю ширину, часть элементов шапки скрывается (см. п.2).

Используйте `@media (max-width: 959px)` и `@media (max-width: 559px)` (или
эквивалент через `min-width`, если так удобнее в конкретном ките — суть та
же, не принципиально).

Убедитесь, что в `<head>` есть
`<meta name="viewport" content="width=device-width, initial-scale=1">` —
если уже есть, ничего не трогайте.

## 2. Шапка (header)

На `<960px`:
- Слева от лого появляется **кнопка-гамбургер** (иконка ≡ из иконочного
  набора этого кита), которая открывает/закрывает сайдбар (см. п.3). На
  десктопе (`≥960px`) эта кнопка скрыта — сайдбар там всегда открыт и своей
  кнопки не имеет.
- Поле поиска в шапке — на `<960px` можно скрыть (`display:none`) либо
  схлопнуть в иконку-триггер, чтобы не ломать раскладку. Выбирайте то, что
  проще реализовать нативными средствами кита.
- Блок пользователя (аватар + ФИО + должность) — на `<560px` оставляйте
  только аватар, текст ФИО/должности скрывайте.
- Кнопка «+ Новая заявка» в шапке — на `<560px` можно оставить только иконку
  без текстовой подписи (текстовая подпись возвращается на `≥560px`).

## 3. Сайдбар → off-canvas на мобильном

На `<960px` сайдбар:
- по умолчанию скрыт за пределами экрана слева
  (`position: fixed; transform: translateX(-100%);` + `transition`);
- открывается по клику на гамбургер — `transform: translateX(0)`;
- поверх контента при открытии показывается полупрозрачный backdrop
  (`position: fixed; inset: 0; background: rgba(0,0,0,.4); z-index: <ниже сайдбара, выше контента>`),
  клик по backdrop закрывает сайдбар;
- клик по любому пункту меню в сайдбаре тоже закрывает его (мобильный UX);
- `z-index` сайдбара выше контента и backdrop, но при этом сам сайдбар не
  должен перекрывать модалку «Новая заявка», если она открыта.

Реализуйте это тем механизмом, который предлагает сам кит, если он у него
есть «из коробки» (проверьте, есть ли встроенный офф-канвас/drawer/sidenav
компонент — по разбору в `RESEARCH.md` он есть у Bootstrap (`offcanvas`),
Materialize (`sidenav` уже поддерживает мобильный overlay-режим «из коробки»,
достаточно добавить триггер-ссылку с классом `sidenav-trigger` и
инициализировать `M.Sidenav`), Vuetify (`v-navigation-drawer` с реактивным
`v-model` + `temporary` на мобильном — самый нативный вариант). Там, где
кит официально ничего для этого не даёт (Bulma, Fomantic-UI, Tailwind без
DaisyUI-drawer, Shoelace, Element Plus, Fluent UI) — реализуйте несколькими
строками vanilla CSS + JS (`classList.toggle`), это нормально и ожидаемо,
как уже отмечено в `RESEARCH.md`.

## 4. KPI-карточки

`grid-template-columns: repeat(4, 1fr)` (или аналог в компонентах кита) →
`repeat(2, 1fr)` на `<960px` → `repeat(1, 1fr)` на `<560px`. Сохраняйте
отступы (`gap`) теми же, просто меняйте число колонок.

## 5. Тулбар (поиск + фильтры + кнопка «Новая заявка»)

На `<960px`: элементы переносятся на несколько строк
(`flex-wrap: wrap`), каждый инпут/селект — `flex: 1 1 auto` или
`width: 100%` на `<560px` (полная ширина, вертикальный стек).

## 6. Таблица заявок

Оберните таблицу в контейнер с `overflow-x: auto` (если такого контейнера
ещё нет) и задайте самой таблице `min-width` (например `760px`), чтобы на
узких экранах она горизонтально скроллилась целиком, а не ломала колонки.
Это универсальное решение — используйте его во всех 9 китах, даже если у
конкретного кита в теории есть более продвинутый «карточный» режим таблицы
(превращать в карточки НЕ нужно, это увеличило бы объём работы и увело бы
страницы разных китов в разную структуру — а горизонтальный скролл сохраняет
100% идентичность колонок между десктопом и мобильным).

## 7. Модалка «Новая заявка»

На `<960px` — `width: 92vw` (или `95vw` на `<560px`), `max-width: none`,
`max-height: 90vh` со внутренним скроллом, если высота не влезает. Поля формы
и так уже в один столбец по исходному брифу — просто следите, чтобы на
маленьком экране не появлялся горизонтальный скролл у самой модалки.

## 8. Что не нужно менять

- Цвета, шрифты, логотип, содержимое (тексты, данные таблицы, поля формы) —
  всё как в `shared/brand.md`, без изменений.
- Десктопный вид `≥960px` должен остаться пиксель-в-пиксель как сейчас.
- Не создавайте отдельный `index.mobile.html` — один файл, адаптивный через
  media queries.

## 9. Финальная проверка

Перед сдачей откройте файл (мысленно или через DevTools-эмуляцию, если
доступно) на ширине **375px** (iPhone) и **768px** (планшет) и убедитесь:
сайдбар не виден по умолчанию и открывается по гамбургеру, ничего не
вылезает за пределы экрана по горизонтали (нет случайного
`overflow-x` на `<body>`/`<html>`), KPI-карточки читаемы, таблица скроллится
внутри своего контейнера, а не «расталкивает» страницу, модалка открывается
на весь экран без обрезки полей.
