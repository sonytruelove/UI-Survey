# Исследование UI-китов и icon-китов для быстрого прототипирования корпоративных интерфейсов

> Контекст: подбор «ассортимента» UI-библиотек для агентного программирования —
> чтобы для конкретного проекта/компании быстро выбирать подходящий кит и знать
> его сильные/слабые стороны ещё до того, как начал писать код.

## 1. Как читать этот документ

- Раздел 2 — категории UI-китов (как вообще делить рынок).
- Раздел 3 — 11 китов, под которые в этом репозитории **реально собраны**
  демо-страницы «Заявки» (`/kits/<slug>/index.html`) — визуально сравнивайте
  их глазами, здесь текстовый разбор плюсов/минусов и отдельно — оценка
  адаптивности/поддержки мобильных платформ у каждого (сводная таблица в 3.12).
- Раздел 4 — ещё ~20 китов, которые стоит знать, но страницы под них не
  строились (осознанно, чтобы не плодить комбинаторику фреймворк×кит-иконок —
  см. пожелание пользователя).
- Раздел 5 — решающая таблица «задача → кит».
- Раздел 6 — иконочные наборы (шрифт-2 этап).

## 2. Категории UI-китов

| Категория | Что это | Примеры |
|---|---|---|
| **CSS-only фреймворки** | Только стили, без JS-логики компонентов (или минимальный JS) | Bootstrap (CSS-часть), Bulma, Foundation, UIkit, Pico.css, Spectre.css |
| **Utility-first** | Атомарные классы, компонентов как таковых нет — вы строите их сами или берёте готовый слой поверх | Tailwind CSS (+ DaisyUI/Flowbite/Preline как слой компонентов) |
| **Классические JS-компонентные киты (framework-agnostic)** | HTML+CSS+JS (обычно на jQuery-подобной или ванильной логике), работают без фреймворка | Bootstrap (JS-часть), Fomantic/Semantic UI, Materialize |
| **Web Components киты** | Кастомные элементы (`<sl-button>`, `<cds-button>`), работают в любом фреймворке или без него | Shoelace, Fluent UI Web Components, Carbon Web Components, Ionic |
| **React-компонентные библиотеки** | Готовые React-компоненты, нужен build (Vite/webpack) | MUI, Ant Design (antd), Chakra UI, Mantine, HeroUI, Blueprint |
| **Vue-компонентные библиотеки** | То же для Vue | Vuetify, Element Plus, PrimeVue, Naive UI, Ant Design Vue, Quasar, Arco Design |
| **Headless / unstyled** | Логика и доступность есть, вёрстки нет — стилизуете сами (часто вместе с Tailwind) | Radix UI, Headless UI, Radix Vue/Reka UI, Ark UI, shadcn/ui (это не библиотека, а генератор кода на Radix+Tailwind) |
| **Корпоративные design-system киты** | Официальный дизайн-язык крупной компании, обычно самые строгие и «тяжёлые» | Fluent UI (Microsoft), Carbon (IBM), Material/MUI (Google), Polaris (Shopify), Atlassian Design System |

Ключевая развилка при выборе: **«чистый фронтенд без сборки» vs «нужен
build-инструмент (npm/Vite/webpack)»**. Для быстрых прототипов/демо (как в
этом репозитории) годятся только первые два столбца — почти всё это можно
подключить через CDN. React/Vue-библиотеки без build чаще всего тоже можно
дёрнуть через CDN UMD/ESM-сборки (как мы и сделали для Vue-семейства), но
это уже компромиссный режим — в проде такие киты почти всегда ставятся через
npm.

## 3. Разбор 11 построенных китов

### 3.1 Bootstrap 5
- **Плюсы:** самый узнаваемый и документированный кит в индустрии; готовые
  паттерны на все случаи (grid, navbar, off-canvas, modal, table, form);
  огромное community, тонны готовых тем/шаблонов; легко нанять
  разработчика, который уже его знает; отличная доступность (ARIA) из коробки.
- **Минусы:** визуально «узнаваем» — сложно не выглядеть типовым сайтом
  2020-х без сильной кастомизации; JS завязан на Popper.js; компонентный
  набор беднее enterprise-китов (нет полноценной data-table, tree, richselect
  «из коробки» — приходится тянуть сторонние плагины).
- **Когда брать:** лендинги, MVP, внутренние тулы, когда команда разношёрстная
  и нужен низкий порог входа; когда критична скорость, а не уникальный стиль.
- **Адаптивность/мобильные платформы:** Отлично. Эталонная mobile-first
  12-колоночная сетка с брейкпоинтами (`sm/md/lg/xl/xxl`), навбар из коробки
  схлопывается в гамбургер, есть готовый off-canvas компонент для мобильного
  сайдбара, утилиты `d-none d-md-block` и т.п. для показ/скрытие по ширине
  экрана. Один из самых сильных вариантов «из коробки» для responsive-вёрстки.

### 3.2 Bulma
- **Плюсы:** чистый Flexbox/Grid CSS без единой строчки JS — максимально
  предсказуем и лёгок в кастомизации через Sass-переменные; приятный
  «модерновый» вид из коробки, без ощущения «бутстрапности».
- **Минусы:** совсем нет JS-компонентов (модалки, dropdown, tabs — логику
  открытия/закрытия пишете сами); нет официальной формы для сложных виджетов
  (datepicker, richtable) — нужны сторонние библиотеки; активность
  разработки ниже, чем у Bootstrap/Tailwind.
- **Когда брать:** статические сайты, лендинги, когда JS-логику всё равно
  пишете сами (SPA на своём стеке) и нужен только слой CSS.
- **Адаптивность/мобильные платформы:** Хорошо на уровне сетки — колонки
  mobile-first с брейкпоинтами (`mobile/tablet/desktop/widescreen/fullhd`),
  navbar имеет мобильное бургер-состояние в разметке — но поскольку у Bulma
  нет своего JS, открытие/закрытие этого бургера и любых off-canvas меню на
  мобильных экранах нужно навесить руками (несколько строк, но это ваш код,
  не кита).

### 3.3 Materialize CSS
- **Плюсы:** классический Material Design 1.0 «из коробки» без React/Angular;
  простая семантика классов; неплохо смотрится для форм и карточек.
- **Минусы:** проект фактически в режиме поддержки, отстаёт от актуального
  Material 3 (Google давно ушёл на Material You); меньше community, чем у
  MUI/Vuetify; часть компонентов (datepicker/select) требуют ручной JS-инициализации.
- **Когда брать:** быстрый прототип «под Google-стиль» без завязки на React/Vue;
  учебные/внутренние проекты, где официальный Material 3 избыточен.
- **Адаптивность/мобильные платформы:** Хорошо. Ранний Material Design
  изначально проектировался под mobile, поэтому `sidenav` нативно умеет
  переключаться между постоянным (десктоп) и выезжающим по бургеру
  overlay-режимом (мобильный) без доп. кода — сильная сторона именно этого
  кита. Слабое место — плотные таблицы (`data-table`) не имеют
  встроенного адаптивного/карточного режима, на узких экранах просто скроллятся.

### 3.4 Fomantic-UI (форк Semantic UI)
- **Плюсы:** самая «человекочитаемая» разметка (`<div class="ui primary button">`)
  — почти естественный язык; богатый набор компонентов и тем; активно
  поддерживаемый форк после остановки оригинального Semantic UI.
- **Минусы:** зависимость от jQuery в классической сборке; крупный CSS/JS
  бандл; вид «из коробки» ощущается немного датированным без темизации;
  ниже популярность/меньше вакансий, где это стек по умолчанию.
- **Когда брать:** внутренние enterprise-панели, где важна скорость чтения
  разметки и не критична производительность бандла.
- **Адаптивность/мобильные платформы:** Средне. Есть сеточная система (16 columns)
  с респонсив-модификаторами (`mobile hidden`, `tablet only` и т.п.), но в
  целом фреймворк исторически не mobile-first — сложные компоненты
  (multi-select dropdown, sidebar-меню) требуют больше ручной доводки под
  тач-интерфейсы и узкие экраны, чем у Bootstrap/Vuetify.

### 3.5 Tailwind CSS + DaisyUI
- **Плюсы:** полный контроль над видом без «борьбы с чужими классами»;
  де-факто стандарт для новых продуктов в 2024–2026; отличная кастомизация
  через `tailwind.config`; DaisyUI добавляет готовые компоненты
  (button/card/modal/badge) поверх утилит, экономя время; огромная экосистема
  (shadcn/ui, Headless UI, Flowbite и т.д. рассчитаны именно на Tailwind).
- **Минусы:** сам по себе Tailwind — не UI-кит, а language для стилей: без
  слоя вроде DaisyUI/shadcn нужно верстать каждый компонент руками; классы в
  разметке «шумные» (utility soup), что усложняет чтение JSX/HTML; через CDN
  (`cdn.tailwindcss.com`) — это play-режим без tree-shaking, годится только
  для прототипов, в проде нужен build (PostCSS/Vite plugin).
- **Когда брать:** практически любой новый продукт с собственным дизайном;
  особенно хорош в связке с React/Vue-компонентами и design-токенами клиента.
- **Адаптивность/мобильные платформы:** Отлично, лучший вариант из всех 11
  для по-настоящему точного контроля над мобильной версткой средствами CSS
  (в отличие от VK UI, где адаптивность — на уровне JS/архитектуры компонентов,
  см. 3.11). Утилиты
  `sm:/md:/lg:/xl:` дают breakpoint-контроль на уровне каждого отдельного
  свойства каждого элемента (а не только готовых компонентов), у DaisyUI есть
  готовый `drawer`-компонент — стандартный паттерн мобильного off-canvas
  сайдбара. Цена за это — вся адаптивность на вашей ответственности, кит не
  делает «магически» адаптивным ничего сам.

### 3.6 Shoelace (Web Components)
- **Плюсы:** framework-agnostic — одинаково работает в React/Vue/Angular/vanilla;
  строгая доступность и клавиатурная навигация из коробки; чистая тема через
  CSS custom properties; лёгкий вес за счёт autoloader (грузит только
  используемые компоненты).
- **Минусы:** Web Components — менее привычная ментальная модель для команд,
  привыкших к React-пропсам (события вместо колбэков, slot вместо children);
  меньше готовых сложных виджетов (data-table нужно строить самому); моложе и
  менее «на слуху» у нанимаемых разработчиков, чем Bootstrap/MUI.
- **Когда брать:** мультифреймворковые продукты/дизайн-системы, которые
  должны работать одинаково независимо от того, что выберет команда
  конкретного модуля.
- **Адаптивность/мобильные платформы:** Средне. Отдельные компоненты
  (`sl-drawer`, `sl-dialog`, кнопки/инпуты) сами по себе гибкие и хорошо
  ведут себя на маленьких экранах, но Shoelace принципиально **не поставляет
  сеточную/layout-систему страницы** — общую responsive-раскладку (колонки,
  брейкпоинты для сайдбара/шапки) вы строите сами через обычный CSS/Grid/Flexbox.

### 3.7 Vuetify 3
- **Плюсы:** самый зрелый Material-кит для Vue; огромный набор готовых
  компонентов (data-table, date-picker, calendar, stepper); тесная интеграция
  с Vue reactivity; хорошая тема-система (`createVuetify({theme:...})`).
- **Минусы:** сильная визуальная узнаваемость Material Design — нужно
  ощутимо кастомизировать, чтобы не выглядеть «дефолтным вьютифаем»; крупный
  бандл; жёстко завязан на Vue — не унести в React-проект.
- **Когда брать:** Vue-проекты с большим количеством форм/таблиц/админ-панелей,
  где скорость разработки важнее уникальности визуала.
- **Адаптивность/мобильные платформы:** Отлично, один из сильнейших в подборке.
  Полноценная responsive-сетка (`v-container/v-row/v-col` с брейкпоинтами
  `xs…xl`), `v-navigation-drawer` нативно переключается между постоянным и
  temporary/overlay-режимом по ширине экрана, а `v-data-table` умеет
  специальный «мобильный» режим — строки превращаются в карточки на узких
  экранах. Именно то, чего не хватает большинству enterprise-Vue-конкурентов.

### 3.8 Element Plus
- **Плюсы:** один из самых мощных enterprise-китов для Vue 3 (родом из
  экосистемы Alibaba/Ele.me); отличные Table/Form/DatePicker/Cascader
  компоненты «для бизнес-приложений»; predictable и последовательный API;
  быстрый через CDN-прототип без build.
- **Минусы:** «китайский enterprise» визуальный характер по умолчанию
  (плотные таблицы, много бордеров) — не всем брендам подходит без
  перестройки; документация местами лучше на китайском, чем на английском;
  требует Vue.
- **Когда брать:** внутренние ERP/CRM/дашборды с большим количеством
  табличных данных и форм — ровно наш кейс с «Заявками».
- **Адаптивность/мобильные платформы:** Средне. Респонсив-сетка `el-row/el-col`
  с брейкпоинтами есть, `el-menu` умеет `collapse`-режим (сворачивание в узкие
  иконки), но это не полноценный мобильный drawer-паттерн, а `el-table` не
  превращается в карточки на мобильном — на узком экране просто горизонтально
  скроллится. Как и большинство «плотных» enterprise-Vue-китов, Element Plus
  проектировался прежде всего под десктопные админки.

### 3.9 Fluent UI Web Components (Microsoft)
- **Плюсы:** официальный дизайн-язык Microsoft — идеален, если продукт
  интегрируется в экосистему Office/Teams/Windows или нацелен на корпоративных
  клиентов, привыкших к этому языку; строгая система design-токенов;
  Web Components — можно использовать без React.
- **Минусы:** самый ощутимо «нишевый» из построенных китов — вне
  Microsoft-контекста может восприниматься как «чужеродный» стиль; CDN/ESM
  подключение без сборщика более хрупкое, чем у остальных (значительная
  часть экосистемы Fluent заточена под React + npm); меньше готовых примеров
  «в вебе» по сравнению с antd/MUI.
- **Когда брать:** внутренние корпоративные инструменты для компаний на
  Microsoft-стеке, интеграции с Teams/SharePoint/Power Platform.
- **Адаптивность/мобильные платформы:** Слабее остальных Web Components-китов.
  Отдельные компоненты гибкие (flex-based), но officialной сеточной/layout-системы
  страницы и готового мобильного nav-компонента у Fluent v2 (веб, на базе FAST)
  нет — общая раскладка и переключение сайдбара в drawer на мобильном пишутся
  вручную. Экосистема Fluent исторически сильнее для десктопных
  Windows/Office-сценариев, чем для mobile web.

### 3.10 HeroUI (бывший NextUI)
- **Плюсы:** самый визуально «модный» и отполированный кит из всей подборки —
  анимации/микро-интеракции, мягкие тени и скругления, плавные переходы
  состояний (наведение, фокус, открытие модалки) идут из коробки за счёт
  Framer Motion под капотом; построен на React Aria — эталонная доступность
  (клавиатурная навигация, ARIA) от той же команды, что делает Radix/Adobe
  Spectrum; сейчас один из самых обсуждаемых китов у инди-разработчиков и
  молодых SaaS-команд, растущий спрос на рынке труда.
- **Минусы:** сильнее остальных завязан на конкретную версию Tailwind-конфига
  (тема подключается как Tailwind-плагин) — без npm/сборщика (Vite/Next.js)
  это самый хрупкий CDN-сценарий из всех 11 построенных страниц, пришлось
  закладывать запасной путь через ручные CSS-токены на случай, если плагин
  темы не подтянется предсказуемо через голый CDN (см. служебную плашку
  внизу `kits/heroui/index.html`); в отличие от antd/Element Plus, набор
  «тяжёлых» enterprise-виджетов (сложные data-grid, org-chart) не такой
  широкий — кит больше про полированные интерфейсные примитивы, чем про
  готовые data-dense паттерны.
- **Когда брать:** современный SaaS-продукт/лендинг+приложение, где визуальный
  «вау-эффект» и приятные анимации важны с первого экрана, а не просто
  функциональная админка; React-стек с реальным сборщиком (Next.js/Vite) —
  для прод-проекта, не для one-off CDN-прототипа.
- **Адаптивность/мобильные платформы:** Хорошо. Компоненты построены на React
  Aria, которая по умолчанию корректно работает с touch/клавиатурой/скринридерами
  на любом размере экрана; собственной grid-системы страницы у HeroUI нет
  (как и у большинства «примитивных» React-китов) — общая мобильная раскладка
  (сайдбар-drawer, брейкпоинты) в демо-странице сделана вручную через CSS, как
  и у Fluent/Element Plus/Shoelace.

### 3.11 VK UI

- **Плюсы:** официальный дизайн-язык ВКонтакте для мини-приложений — из всей
  подборки это единственный кит, спроектированный **мобильным по умолчанию**,
  а не «десктопный кит с адаптивом сверху»; `AdaptivityProvider` +
  `SplitLayout`/`SplitCol` дают настоящую JS-адаптивность (реальная
  перестройка дерева компонентов по ширине вьюпорта через
  `useAdaptivityWithJSMediaQueries`, а не только CSS-медиазапросы), модальные
  окна на мобильном сами превращаются в нативно выглядящий bottom-sheet без
  ручной подгонки под ширину экрана; аккуратная система тем через публичные
  CSS-переменные (`--vkui--color_*`) — тему можно перекрасить, не трогая
  внутренние классы компонентов; отличная проработка «плотных» списковых
  паттернов (`SimpleCell`/`RichCell`/`Group`) для карточных интерфейсов.
- **Минусы:** нет вообще никакой desktop-ориентированной data-table —
  компонента для табличных данных в ките попросту нет (см. врезку внизу
  `kits/vkui/index.html`), потому что VK UI исторически не для этого
  проектировался; сильная визуальная ассоциация с интерфейсом ВКонтакте,
  которую тяжело полностью перебить кастомной темой; вне контекста
  мобильных мини-приложений/VK-экосистемы выглядит нишевым выбором;
  документация и комьюнити ощутимо меньше, чем у MUI/antd/Vuetify.
- **Когда брать:** VK Mini Apps (собственно их родная среда); мобильные web-
  и гибридные приложения, где на первом месте — телефон, а десктоп/планшет
  вторичны; продукты, которым нужна настоящая (не только визуальная)
  адаптивность интерфейса между платформами без двух отдельных кодовых баз.
- **Адаптивность/мобильные платформы:** Отлично, сильнейший результат в
  подборке — и единственный кит здесь, где мобильная адаптивность встроена
  в саму архитектуру, а не «дорисована» поверх десктопной версии. `SplitLayout`/
  `SplitCol` умеют по-настоящему скрывать/показывать колонки по реальной
  ширине вьюпорта (не только CSS), `Tabbar` — готовый паттерн нижней
  мобильной навигации, модалки (`ModalRoot`/`ModalPage`) сами переключаются
  между десктопным диалогом и мобильным bottom-sheet. В демо-странице
  собственная схема drawer-сайдбара всё равно сделана вручную поверх
  `SplitLayout` (см. комментарий в исходнике) — ради идентичного UX с
  остальными 10 китами при сравнении, а не из-за нехватки возможностей кита.

### 3.12 Сводка по адаптивности (11 построенных китов)

| Кит | Оценка | Коротко |
|---|---|---|
| VK UI | ⭐⭐⭐⭐⭐ Отлично | Единственный кит здесь, спроектированный мобильным по умолчанию — настоящая JS-адаптивность (`SplitLayout`/`AdaptivityProvider`), не только CSS |
| Bootstrap 5 | ⭐⭐⭐⭐⭐ Отлично | Эталонный mobile-first grid + бургер-навбар + off-canvas «из коробки» |
| Tailwind + DaisyUI | ⭐⭐⭐⭐⭐ Отлично | Точечный breakpoint-контроль над каждым свойством + готовый mobile drawer |
| Vuetify 3 | ⭐⭐⭐⭐⭐ Отлично | Responsive grid + drawer авто-переключение + мобильный режим таблицы (карточки) |
| Materialize CSS | ⭐⭐⭐⭐ Хорошо | Sidenav с нативным mobile-overlay режимом, но таблицы не адаптивны |
| Bulma | ⭐⭐⭐ Средне | Хорошая mobile-first сетка, но бургер/off-canvas — своя JS-логика |
| Fomantic-UI | ⭐⭐⭐ Средне | Респонсив-грид есть, но не mobile-first по духу, требует доводки |
| Element Plus | ⭐⭐⭐ Средне | Grid + collapse-меню есть, но таблица не адаптируется под мобильный |
| Shoelace | ⭐⭐⭐ Средне | Компоненты гибкие, но layout/grid страницы — целиком на вас |
| HeroUI | ⭐⭐⭐ Средне | React Aria даёт корректную работу компонентов на touch/клавиатуре, но своей grid-системы страницы нет — раскладка сайдбара/брейкпоинтов вручную |
| Fluent UI Web Components | ⭐⭐ Требует доработки | Нет своей grid/layout-системы и mobile nav-паттерна, всё вручную |

**Важно:** это оценка возможностей самого кита. Изначально десктопные
демо-страницы верстались под десктоп (≥1280px) ради честного визуального
сравнения, затем все страницы (включая VK UI, добавленный позже) дополнительно
адаптированы под мобильные экраны по единому брифу (см. `shared/responsive.md`)
— сайдбар на узких экранах превращается в выезжающую панель, KPI-карточки
складываются в 1–2 колонки, таблица скроллится горизонтально в своём
контейнере, формы занимают весь экран. Это намеренно одинаковый UX-паттерн
для всех 11 китов ради честного сравнения — даже там, где у кита (как у VK UI)
есть собственная, более «родная» альтернатива.

## 4. Другие киты, которые стоит знать (без построенных демо-страниц)

> Carbon Design System, PrimeVue и Ant Design Vue **были в первой версии
> демо-подборки**, но их страницы полагались на нетиповые ESM-CDN эндпоинты
> (esm.sh-бандлинг без npm/сборщика) и не удалось надёжно проверить их
> рендеринг в песочнице без доступа к этим CDN — по итогам ревью страницы
> получились заметно кривыми и были убраны из демо-набора. Сами киты как
> технологии остаются полноценными и стоящими знакомства вариантами —
> см. их разбор ниже; для реального проекта их стоит подключать через
> npm/бандлер, а не через голый CDN на one-off HTML-страницу.

| Кит | Экосистема | В двух словах |
|---|---|---|
| **Carbon Design System (IBM)** | Web Components / React | Один из самых продуманных enterprise/data-dense дизайн-языков — строгая типографика, сетка `cds-grid` (16 колонок, чёткие брейкпоинты), отличная доступность; визуально консервативный «квадратный» стиль; через CDN без сборщика доступна не вся функциональность — для прода нужен npm |
| **PrimeVue** | Vue 3 (+ PrimeReact/PrimeNG) | Самый широкий набор enterprise-виджетов среди Vue-китов (DataTable с `responsiveLayout="stack"` для мобильных, Kanban, Timeline), гибкая система тем (Aura/Lara/Material); новая Pass Through/design-tokens система тем имеет кривую обучения |
| **Ant Design Vue** | Vue 3 (+ antd для React) | Портирует эталонный enterprise design-language Ant Design (Alibaba) на Vue, продуманная темизация через `ConfigProvider`, `Sider breakpoint` для авто-drawer на мобильном; сильный узнаваемый «Ant-стиль» требует дисциплины при кастомизации |
| **MUI (Material UI)** | React | Самый популярный React-кит enterprise-уровня, эталонная реализация Material Design для React, огромная экосистема (MUI X — таблицы/графики/датапикеры) |
| **Chakra UI** | React | Лёгкий, дружелюбный API, отличная доступность и тёмная тема из коробки, менее «представительный» вид, чем MUI/antd |
| **Mantine** | React | Молодой, но очень полный (100+ компонентов + hooks), нативная поддержка форм/дат/нотификаций, быстро растущая популярность |
| **Radix UI / shadcn/ui** | React + Tailwind | Headless-примитивы (Radix) + генератор копируемого кода компонентов на их основе (shadcn) — код живёт в вашем репозитории, максимальный контроль над стилем, сейчас один из самых модных подходов 2024–2026 |
| **Ark UI / Headless UI** | React/Vue/Solid | Headless-логика без вёрстки, используется как база под свой дизайн |
| **Blueprint** | React | Кит от Palantir, заточен под data-dense desktop-like приложения (аналитика, дашборды) |
| **Quasar** | Vue | «Всё в одном» — UI-кит + сборка под Web/Mobile(Capacitor)/Desktop(Electron) из одной кодовой базы |
| **Naive UI** | Vue 3 | Полностью на TypeScript, лёгкий, современный вид, popular в новых Vue 3 проектах |
| **Arco Design / TDesign** | React & Vue | Enterprise-киты от ByteDance и Tencent соответственно — альтернативы Ant Design с похожим уровнем зрелости |
| **Ionic Framework** | Web Components / React / Vue / Angular | Заточен под mobile-first и гибридные приложения (Capacitor/Cordova), нативно выглядящие компоненты под iOS/Android |
| **Foundation (ZURB)** | CSS + JS | Один из «дедушек» CSS-фреймворков наравне с Bootstrap, сильный responsive-grid, сейчас нишевая популярность |
| **UIkit** | CSS + JS | Модульный лёгкий фреймворк, богатая коллекция готовых блоков/паттернов |
| **Pico.css / Spectre.css / Skeleton** | CSS-only | Минималистичные классless/lightweight фреймворки — стилизуют голый semantic HTML почти без классов, хороши для микро-проектов и документации |
| **Bootstrap-Vue / React-Bootstrap** | Vue/React | «Обёртки» классического Bootstrap в компоненты соответствующего фреймворка |
| **Polaris** | React | Design-system Shopify — если продукт это Shopify-приложение или e-commerce admin |
| **Atlassian Design System** | React | Для инструментов в духе Jira/Confluence, строгий корпоративный стиль |

## 5. Как выбирать кит под задачу

| Ситуация | Рекомендуемые киты | Почему |
|---|---|---|
| Быстрый лендинг/MVP, разношёрстная команда | Bootstrap 5, Bulma | низкий порог входа, тонны готовых паттернов |
| Уникальный бренд, свой дизайн с нуля | Tailwind + (DaisyUI или shadcn/ui) | максимальный контроль без борьбы с чужими классами |
| Внутренняя админка/CRM с обилием таблиц и форм (наш кейс «Заявки») | Ant Design (Vue/React), Element Plus, PrimeVue/PrimeReact, Carbon | готовые data-table/form-паттерны, продумано под плотные бизнес-данные |
| React-продукт, нужна зрелая экосистема | MUI, Mantine, antd | наибольшее число готовых компонентов и интеграций |
| Современный SaaS-продукт, важен «отполированный» визуал из коробки | HeroUI, Mantine | анимации/скругления/микро-интеракции по умолчанию, без ручной доводки |
| Vue-продукт | Element Plus, PrimeVue, Vuetify, Naive UI | зрелость + нативная реактивность Vue |
| Мультифреймворковая дизайн-система/виджеты для встраивания куда угодно | Shoelace, Fluent UI Web Components, Carbon Web Components | Web Components независимы от фреймворка хоста |
| Продукт для Microsoft-экосистемы (Teams/SharePoint) | Fluent UI | ощущается «родным» для этой аудитории |
| Data-dense инженерный/финтех продукт | Carbon, Blueprint, PrimeVue/PrimeReact | заточены под плотные таблицы и мониторинг |
| Максимальный контроль над дизайном + нужна доступность «из коробки» | Radix UI/shadcn, Ark UI, Headless UI + своя CSS-система | headless-логика, вёрстка полностью ваша |
| Мобильное/гибридное приложение | Ionic, Quasar | одна кодовая база под web+iOS+Android |
| Мобильный web-продукт с десктопной версией «на вырост», VK Mini Apps | VK UI | единственный построенный кит с настоящей (не только CSS) адаптивностью между платформами из коробки |
| Документация/микро-сайт без сборки | Pico.css, Spectre.css | classless CSS, почти без разметки |

**Как выбирать icon-кит:** по умолчанию — иконки, «родные» для выбранного
UI-кита (см. столбец в разделах 3/4) — они гарантированно совпадают по
насыщенности штриха/сетке с остальными компонентами. Если нужен набор с
широчайшим покрытием тематических/отраслевых иконок (например,
энергетика/инфраструктура: трансформаторы, ЛЭП, кабели) — из типовых наборов
лучше всего покрывают такие темы **Tabler Icons** и **Phosphor Icons**
(широта тематик), для узкоспециализированных инженерных пиктограмм чаще
приходится заказывать/рисовать кастомный набор отдельно — готовых
«энергетических» icon-китов на рынке практически нет.

## 7. Вывод

Нет универсально «лучшего» кита — выбор всегда определяется: (1) фреймворком
проекта (или его отсутствием), (2) плотностью данных в интерфейсе
(лендинг vs дата-тяжёлая админка), (3) тем, насколько бренд обязан визуально
отличаться от «дефолтного» вида кита, и (4) наличием build-инструментов в
проекте. Для быстрого агентного прототипирования под конкретную компанию
практичнее всего держать в арсенале по одному сильному представителю каждой
строки таблицы из раздела 5 — тогда для любого входящего запроса можно сразу
понять, какой кит взять за основу, вместо разработки с нуля.
